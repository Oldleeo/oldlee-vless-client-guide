# VLESS 客户端排障清单

先判断现象，再改一个变量。不要一次打开“允许不安全”、改 SNI、改传输方式、换 DNS，最后反而不知道是哪一步修好的。

## 1. 连接超时

按顺序检查：

1. 地址是否仍然有效，DNS 是否能解析。
2. 端口是否填对，客户端网络是否能访问该端口。
3. UUID 是否属于这条节点，而不是复制了另一条节点的 UUID。
4. REALITY 公钥、短 ID、SNI、指纹是否来自同一条链接。
5. 手机系统时间是否自动同步；时间误差过大可能导致 TLS/REALITY 握手失败。
6. 先关闭多路复用和自定义片段，使用最小配置测试。

## 2. 显示已连接但网页打不开

- 先切到全局 / Proxy 模式。
- 确认系统代理或 VPN 权限已开启。
- 检查 DNS 设置，不要把 DNS 填成不可达的内网地址。
- 关闭其他 VPN、代理软件和浏览器扩展，避免端口冲突。
- 查看客户端日志，区分“握手成功但上游无响应”和“根本没有连到服务器”。

## 3. 导入后字段乱码或出现一堆编码

常见原因：

- 复制的是 Markdown 链接，里面有反斜杠转义；
- 复制时包含了前后引号、空格或换行；
- 把订阅地址当成单节点链接粘贴；
- 从截图 OCR 识别，导致字符被替换。

正确做法：复制原始单行 URI，确认开头是 `vless://`，结尾是节点名称，不要手动改编码。

## 4. 速度很慢

- 先做直连与代理的 A/B 测试。
- 分别测试 Wi-Fi、蜂窝、不同时间段。
- 确认是否经过住宅代理或二次中转；身份更稳定通常意味着额外延迟。
- 看丢包和抖动，不要只看一次下载峰值。
- 关闭不必要的全局代理、脚本和流量重写。

## 5. Shadowrocket 能连，电脑端不能连

- 检查两端是否导入的是同一条 URI。
- 检查桌面客户端的 Xray core 是否过旧。
- 确认系统代理开关，而不是只选中了节点。
- 先关闭 UDP、多路复用和自定义 HTTP/2 选项，回到 TCP + REALITY 的原始参数。

## 6. 电脑能连，Shadowrocket 超时

- 手动检查 SNI、Public Key、Short ID 和 Fingerprint。
- TLS 必须开启，Security 应为 REALITY。
- `允许不安全` 默认关闭。
- 清除 Shadowrocket 中旧的同名节点，再重新导入。
- Wi-Fi 与蜂窝网络各测试一次，排除本地网络策略差异。

## 7. 最小化复现记录

每次排障只记录这些非敏感信息：

```text
客户端：XrayN / v2rayN / Shadowrocket
系统：Windows / macOS / iOS
核心版本：<CORE_VERSION>
网络：Wi-Fi / 蜂窝
模式：规则 / 全局 / 直连
现象：超时 / 无网络 / 慢 / 部分网站失败
时间：<TEST_TIME>
```

不要把真实 UUID、完整链接、API Key 或 SSH 私钥贴进 Issue。
